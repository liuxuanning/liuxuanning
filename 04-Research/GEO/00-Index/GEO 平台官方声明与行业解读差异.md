# GEO 平台官方声明与行业解读差异

## 核心原则

平台官方声明通常描述产品能力、接口、抓取规则或使用规范；行业解读常把这些能力延伸成优化方法、排名机会或商业价值。

两者必须分开记录。

## 证据等级

- 官方声明：`evidence/global-platform-official`、`evidence/domestic-platform-official`。
- 平台生态线索：`evidence/domestic-platform-ecosystem`，不得写成平台官方结论。
- 行业解读、服务商材料、媒体报道、市场规模或效果数字：需另标为 vendor、media 或 market claim，不得混入官方声明。

## 判定规则

- 官方帮助中心、官方开发者文档、官方云产品页：记录为官方机制材料。
- 服务商白皮书、榜单、案例页：记录为市场叙事或厂商材料。
- 媒体报道：记录为行业热度与话语变化。
- 开发者社区投稿：除非明确为官方产品文档，否则不标为平台官方。
- 平台生态或社区内容可以作为找源线索，但必须继续追溯到官方帮助中心、开发者文档、协议或产品页。

## 常见差异

| 官方声明 | 行业解读可能延伸 | 处理方式 |
|---|---|---|
| 平台支持联网搜索 | 内容可以被 AI 搜索引用 | 标注为假设或厂商主张 |
| 平台展示来源 | 可通过 GEO 提升引用概率 | 需要实测或案例证据，本阶段不验证 |
| 平台提供搜索 API | 企业可以系统化监测 AI 可见性 | 可作为产品机会，不作为效果证明 |
| 平台有智能体生态 | 品牌可以进入 Agent 推荐链路 | 先记录生态入口，不推断推荐效果 |

## 可证明与不可证明

- 可证明：平台公开说明了某项能力、接口、规则、协议或生态入口。
- 不可证明：该能力一定带来引用概率提升、排名提升、转化提升或品牌推荐。
- 可作为假设：如果平台展示来源或提供搜索 API，则可能存在监测、内容结构化和信息源治理机会，但必须在方案中标注证据层级。

## 使用要求

- 引用平台资料时，必须同时写清“来源性质”和“能证明什么”。
- 从官方声明推导运营建议时，中间必须增加“推论”或“假设”标记。
- 涉及效果、排名、ROI、增长率、推荐概率等说法时，不能只用官方资料支撑。
