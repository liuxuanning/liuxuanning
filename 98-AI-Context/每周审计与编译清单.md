# 每周审计与编译清单

## 使用方式

每周复制本清单到新的审计记录，建议命名为：

`98-AI-Context/Knowledge Base Audit - YYYY-MM-DD.md`

本清单只做检查、编译和记录，不批量删除文件，不移动大量目录。

## 1. Inbox 清理

- [ ] 检查 `00-Inbox/Downloaded` 是否有新采集资料。
- [ ] 检查 `00-Inbox/Cleaned` 是否有待分流资料。
- [ ] 给新资料补齐 `source`、`author`、`published`、`captured`、`status`、`topics`、`tags`。
- [ ] 标记低价值资料为待搁置，不强行进入研究区。
- [ ] 选择本周值得编译的 3-10 条资料。

## 2. 研究编译

- [ ] 将高价值资料编译进 `04-Research` 的对应主题。
- [ ] 区分官方资料、论文/报告、可信媒体、行业观察、个人观点。
- [ ] 提取本周新增结论。
- [ ] 标记冲突观点和未验证假设。
- [ ] 为每条重要结论保留来源链接或来源笔记链接。

## 3. Topic Hub 更新

- [ ] 检查本周涉及的 Topic Hub 是否存在。
- [ ] 更新 `Current Thesis`。
- [ ] 更新 `Key Questions`。
- [ ] 更新 `Canonical Notes`。
- [ ] 更新 `Source Layer` 和 `Compiled Knowledge`。
- [ ] 更新 `Gaps And Review Queue`。
- [ ] 在 `Weekly Compile Log` 写入本周记录。

## 4. 输出回流

- [ ] 检查本周聊天、方案、脚本、项目推进中是否有可沉淀内容。
- [ ] 研究结论回流到 `04-Research`。
- [ ] 内容选题或脚本回流到 `05-Content`。
- [ ] 项目状态或需求回流到 `06-Projects`。
- [ ] 长期偏好、决策、经验、教训回流到 `97-AI-Memory`。
- [ ] AI 操作规则、提示词、流程回流到 `98-AI-Context`。

## 5. 健康检查

- [ ] 检查孤立 Markdown 文件数量。
- [ ] 检查重复文件名。
- [ ] 检查空目录。
- [ ] 检查断链或缺少反向链接的主题页。
- [ ] 检查没有来源的研究结论。
- [ ] 检查过期或需要复核的笔记。
- [ ] 检查是否有密钥、Token、Webhook URL 等敏感信息外泄。

## 7. 审计边界

- 本清单不删除文件。
- 本清单不批量移动文件。
- 涉及删除时，只能由用户确认后一次删除一个明确路径的文件。
- 涉及密钥、Token、Webhook URL 时，只记录“需要本地检查”，不复制具体值。
