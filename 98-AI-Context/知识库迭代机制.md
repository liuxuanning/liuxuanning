# 知识库迭代机制

## 目标

把当前 Obsidian 知识库从“资料存放处”升级为“持续编译系统”：人负责判断什么值得进入系统，AI 负责把原始资料持续编译成可检索、可复用、可追溯的知识。

## 核心原则

- 原始资料不急着总结，先保留来源、作者、发布时间、采集时间和原文。
- 编译知识必须能追溯到原始资料或研究笔记。
- 结论、决策、偏好、流程要分开放，不把“看到过的信息”误当成“已经确认的规则”。
- Topic Hub 是主题入口，不只是链接列表；它要承载当前理解、关键问题、证据缺口和输出机会。
- 每周固定做一次审计和编译，少量持续更新优先于一次性大重构。

## 分层规则

| 层级 | 目录 | 作用 | 改写规则 |
|---|---|---|---|
| 原始层 | `00-Inbox/Downloaded`、`Clippings` | 保存网页、帖子、视频、PDF 等原始捕获 | 不改写正文，只补元数据 |
| 清洗层 | `00-Inbox/Cleaned` | 去噪、补标签、判断是否值得进入研究区 | 可以轻度整理，不产出最终结论 |
| 研究层 | `04-Research` | 形成主题笔记、证据笔记、框架笔记 | 可以由 AI 编译，但必须保留来源 |
| 内容层 | `05-Content` | 选题、脚本、文章、发布材料 | 可从研究层派生，需标明依据 |
| 项目层 | `06-Projects` | 项目状态、需求、里程碑、复盘 | 只记录与项目推进相关的知识 |
| 记忆层 | `97-AI-Memory` | 长期有效偏好、决策、经验、教训 | 只写入已经确认且可复用的内容 |
| 上下文层 | `98-AI-Context` | AI 操作规则、Topic Hub、工作流、审计报告 | 维护系统规则和主题入口 |

## 资料进入流程

1. 采集到 `00-Inbox/Downloaded` 或 `Clippings`。
2. 补齐元数据：`title`、`source`、`author`、`published`、`captured`、`status`、`topics`、`tags`。
3. 判断处理方式：
   - 无价值：保留或归档，不进入研究区。
   - 有参考价值：清洗后进入 `04-Research`。
   - 可直接支持项目：同步链接到 `06-Projects`。
   - 可直接支持内容：同步链接到 `05-Content`。
4. 更新相关 Topic Hub 的“Source Layer”或“Compiled Knowledge”。

## 编译规则

AI 编译研究笔记时，必须输出以下内容：

- 当前结论：能明确回答什么问题。
- 证据来源：来自哪些原始资料或研究笔记。
- 证据等级：官方资料、论文/报告、可信媒体、行业观察、个人观点。
- 冲突与不确定：哪些说法互相矛盾，哪些仍未验证。
- 可复用输出：能转成方案、内容、提示词、项目需求或长期记忆的部分。
- 回流位置：更新到哪个 Topic Hub、项目页、内容页或记忆页。

## Topic Hub 维护规则

每个重要主题都要有一个 Hub。Hub 至少维护：

- Scope：这个主题包含什么，不包含什么。
- Current Thesis：当前最可信的理解。
- Key Questions：下一步要追问的问题。
- Canonical Notes：最重要的入口笔记。
- Source Layer：原始或半清洗资料。
- Compiled Knowledge：已经综合过的研究笔记。
- Outputs And Decisions：由这个主题产生的内容、项目和决策。
- Gaps And Review Queue：缺口、冲突、过期内容和待综合资料。
- Weekly Compile Log：每周审计和编译记录。

## 输出回流规则

每次产生有长期价值的输出，都要决定是否回流：

| 输出类型 | 回流位置 |
|---|---|
| 研究结论 | `04-Research` 和相关 Topic Hub |
| 内容选题、脚本、文章 | `05-Content` |
| 项目状态、需求、复盘 | `06-Projects` |
| 长期偏好、成功经验、失败教训、稳定决策 | `97-AI-Memory` |
| AI 使用规则、提示词规范、知识库流程 | `98-AI-Context` |

## 每周节奏

- 周内：只采集，不强迫整理。
- 每 2-3 天：清理一次 Inbox，把明显有价值的资料推进研究层。
- 每周：执行一次 `每周审计与编译清单`。
- 每月：重看 Topic Hub，合并重复主题，更新长期记忆和操作上下文。

## 验收标准

- 新资料 7 天内被清洗、归类或明确搁置。
- 重要主题都有 Topic Hub，且不是空索引。
- 研究结论能追溯到来源。
- 输出没有只停留在聊天里，能回流到对应目录。
- AI 开始新任务时，可以先读相关 Hub 和上下文，而不是重新解释背景。

## 禁止事项

- 不做大规模目录迁移，除非有明确迁移方案和人工确认。
- 不批量删除文件或目录。
- 不把未验证观点写成长期记忆。
- 不把原始资料改写成看似确定的结论。
- 不在笔记中保存或暴露密钥、Token、Webhook URL。
